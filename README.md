# Chore Rotation for Home Assistant

A deterministic household-chore scheduler. It **does not send notifications** or require a calendar. A sensor publishes a map of each person to their outstanding chores, including unfinished occurrences from previous days. Use normal Home Assistant automations to consume it.

## Installation

This is an installable **custom integration** repository, ready to publish as a GitHub repository for the Home Assistant Marketplace (HACS). To install it, upload this directory to your own public GitHub repository, add that repository as a custom integration in the Marketplace, install, and restart Home Assistant. Alternatively, copy `custom_components/chore_rotation` into `<config>/custom_components/` and restart HA.

Add **Chore Rotation** in **Settings → Devices & services → Add integration**. It starts with the chore list discussed and two placeholder people.

## Management interface

After installation, open **Chore Rotation** from the Home Assistant sidebar. The integration includes a management panel and does not require another HACS frontend installation.

- **Chores & assignments:** Edit all chores on one page. Use +/- to adjust each person's number of shares. Click a slot in the repeating assignment sequence to rotate its owner. Use arrows to change task order, and add or remove tasks within each frequency group.
- **People:** Add, rename and remove people. Removing someone removes their shares; if a task would otherwise have no assignee, it is assigned to the first remaining person.
- **Today's chores:** Tick off individual occurrences. Unchecked chores stay visible on subsequent days and after restarts. Completed occurrences disappear.

All modifications are held locally until **Save all changes** is clicked. **Discard** restores the last saved configuration. Changes to chores or people immediately update the HA sensor after saving. The old one-operation-at-a-time **Configure** flow has been removed. The sidebar management panel is the only configuration interface. Existing configuration is preserved.

The order of shares matters: for daily cooking, `A A A A A A B` gives B every Sunday when the cycle is aligned to the reference Monday. For a weekly chore, `A B` alternates by week. Person percentages specify proportions, while individual slots control their ordering. No notifications are sent by this integration.

## Output entity

The sensor is named **Chore Rotation Today**, usually `sensor.chore_rotation_today`. The numerical sensor state is the number of outstanding (unchecked) chore occurrences. Attributes contain:

```yaml
date: "2026-11-22"
assignments:
  Person A:
    - Einkaufen
    - Spülmaschine einräumen
  Person B:
    - Kochen
    - Küche saubermachen
```

The mapping above illustrates the *format*, not a guaranteed list for that date.

To read the list for a person from an automation template:

```jinja2
{{ state_attr('sensor.chore_rotation_today', 'assignments').get('Person A', []) }}
```

For notifications, create a **time-triggered automation** that reads this attribute and calls the mobile-app notification action. No notifications are generated by the integration. New occurrences are appended at midnight or startup and completed ones are removed when ticked off. If HA was offline on previous days, their missed occurrences are not backfilled. Unfinished occurrences already recorded persist across restarts.

## Scheduling rules

Each task is configured separately in the sidebar dashboard. In addition to its repeating **person assignment sequence**, a task has its own calendar recurrence:

- **Daily:** Every N days (default: every day).
- **Weekly:** Selected weekdays, every N weeks (e.g. Monday with interval 2 = every second Monday).
- **Twice weekly:** Two selected weekdays, every N weeks (default: Monday and Thursday every week).
- **Monthly:** A selected day of the month, every N months (e.g. the 15th each month).
- **Quarterly:** A selected day of the month, every N months (default: every three months, in January/April/July/October).

For weekly/monthly schedules the **Reference date** (anchor date) determines which week/month is the first in the cycle. The relevant week starts on Monday. For example, selecting a Monday, a two-week interval and the reference date `2026-11-16` gives November 16, November 30, December 14, etc. Monthly tasks on the 29th, 30th or 31st occur on the final calendar day in shorter months.

Assignment cycles advance once per scheduled occurrence and are independent per task. They do not reset at month, quarter or week boundaries. Assignment and scheduling are both calculated from dates rather than volatile counters. HA restarts do not move assignments; missed dates are not made up.

**Upgrade note:** Tasks from v0.3.1 had no individual dates. They retain their people and allocation sequences and receive editable default recurrence rules on load (daily each day, twice weekly Mon/Thu, weekly Monday, monthly first of month, quarterly first day of Jan/Apr/Jul/Oct). Save once in the sidebar dashboard to persist those dates. This intentionally replaces the previous algorithm's automatic distribution of tasks across a period.

The HA sensor remains `sensor.chore_rotation_today`. Existing notification automations do not need changes.

The integration tracks completion of each chore occurrence and carries unfinished occurrences forward, but does not send notifications or balance workloads.

## Assignment methods (v0.5.0)

In **Chores & assignments**, each chore has an **Assignment method** selector:

- **Repeating sequence** (default): keep the existing ordered rotation. A weekly `A B` chore alternates between people across weeks.
- **Fixed weekdays**: choose one person for each weekday. For daily cooking, assign Monday to B and the other six days to A. The same weekday will always belong to the same person.
- **Sequence with weekday overrides**: set a person on selected weekdays and leave the others as **Use sequence**. Overrides replace the assignee on that date but do not advance or modify the underlying date-derived sequence.

The weekday assignments use the chore's **actual scheduled date**, not the date of configuration. For monthly and less frequent tasks, only the weekdays on which a task actually occurs matter. The existing numeric share controls still edit the fallback sequence; when fixed weekdays are selected, those percentages do not describe the actual weekly distribution.

Older configurations automatically continue in **Repeating sequence** mode until edited. The published `sensor.chore_rotation_today` format is unchanged, as are existing notification automations.

## Direct links to dashboard tabs

The dashboard supports direct links to tabs, including `/chore-rotation#today` for the Today's chores tab. Use this path as the iOS Companion App notification `url` to open the daily overview.

## Persistent completion tracking (v0.6.0)

The **Today's chores** page now shows checkboxes for all pending occurrences, including chores from previous dates. Checking a chore removes that occurrence from the pending list. A new occurrence of a recurring chore is added independently even when an older one is still outstanding. Each occurrence has a stable date-plus-task identifier and its original assignee.

Pending occurrences and the last processed date are saved to Home Assistant's `.storage` using the native `Store` helper, separately from the config entry containing your people and chores. Upgrades preserve both task configuration and pending records. On the first run of v0.6.0, the current day's occurrences become pending; the integration cannot infer whether tasks due on earlier days were completed, so it does not create a historical backlog.

The existing `assignments` sensor attribute and notification automation remain compatible, except that `assignments` now includes all unfinished chores, including older occurrences. A separate `pending` attribute contains the individual occurrence IDs, dates and assignees. The sensor entity ID and dashboard URL remain unchanged.


## v0.6.1: Access for household members

The sidebar panel is now available to non-administrator Home Assistant users.
Non-administrators can view outstanding chores and mark individual occurrences complete.
Only administrators can edit the people, recurrence rules, task definitions and distributions.
This panel is registered by the integration, so it does not appear under Home Assistant's ordinary dashboard settings.
Existing chores and outstanding items remain in Home Assistant's persistent storage when updating.
